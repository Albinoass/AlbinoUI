# First in-game acceptance test

**All live checks below are pending.** Use a Rogue in a safe area, with other action-bar addons disabled. Record the character, locale, resolution, UI scale and exact build. Back up WTF first: changes to these bars change native action slots.

1. Install the extracted `AlbinoUI` folder under `World of Warcraft\_forever_\Interface\AddOns`. Confirm there is exactly one `AlbinoUI` directory between AddOns and `AlbinoUI.toc`.
2. Enable the addon and enable the client's Lua error display in its supported developer/error settings. An optional native macro `/console scriptErrors 1` enables errors on clients supporting that CVar; this is not an Albino UI slash command.
3. Open Game Menu → Options → AddOns → Albino UI (or Interface → AddOns). Record the version/build, interface and Lua version shown at the top. Confirm no startup error and compare against 16001. Do not hide a mismatched interface warning without recording the mismatch.
4. Type `/albino unlock`. Move the main bar, secondary bar, cooldown tracker, resources and swing section separately using their handles. None should move another section. Type `/albino lock`; all handles disappear. Repeat at 1080p and 1440p if available and at scale 0.75, 1 and 1.5. Check screen clamping and reload persistence.
5. Out of combat, drag a learned spell from the spellbook onto an empty main button. Confirm its native icon and tooltip. **Click it** and verify a real cast. Repeat with a secondary button. Do this while layout is locked too.
6. Replace an assigned spell; move one into an empty button; swap two populated buttons; move between bars; drag a spell off the bar and clear the cursor using the game. Verify the actual spell that executes after each operation, not just the icon. Verify unrelated slots stay unchanged.
7. Bind native Action Button 1 to a key and an alternate key, and Bottom Left Action Button 1 to a different key. Confirm both main keys and the secondary key cast the correct spells. Then test direct entries under Key Bindings → Albino UI. Test modifier self/focus casting where the client supports it. Record any ACTION_BLOCKED or ADDON_ACTION_FORBIDDEN errors.
8. Enter stealth. Assign an appropriate stealth spell to a primary button and verify the native stealth slot is distinct. Leave/re-enter stealth and verify normal/stealth placements persist and keys follow the correct page. Confirm secondary slots never switch or overwrite primary/stealth slots. Repeat Vanish/stealth state changes during combat where permitted.
9. Set each bar independently to 1, 6 and 12 buttons. Change size/spacing, visibility and fading. Hidden slots must return with their original spells. Mouseover fading must retain functional clicks/keys; moving to tooltips must not cause click loss. Inspect underlying native bars if a hidden custom bar still has an active native binding.
10. Fight a safe target. Verify real health and energy, optional numbers, actual maximum power, combo generation, spending and target switches. Check energy responsiveness while spending/regenerating. Verify out-of-range icons turn red, insufficient-energy icons blue and otherwise unusable actions gray. Watch native cooldown shading and remaining numbers after Kick or another learned cooldown.
11. While in combat, request unlock and a count/size/visibility/scale change, then Apply. Confirm no protected mutation error, no disappearing combat buttons, and that the last requested settings take effect after combat. Try dragging a spell during combat: it must not change slots. Check native action execution continues throughout. Also test entering combat while a handle drag is in progress and releasing it; confirm safe deferred stop/save afterward.
12. Change tracked spell IDs, include an unlearned ID and an empty list. Verify only learned spells render, native icons follow learned ranks, ready visibility toggles, cooldown text counts down and the tracker never casts anything.
13. Dual wield and auto-attack, inspecting the swing tooltip. If the client supplies public hand-specific swing events, verify each hand starts only on its own observed event, expires without repeating, reacts conservatively to casts/equipment/speed changes and clears on combat exit/death. If Forever supplies no such events, **blank bars are the expected fallback**; record this limitation rather than calling the timer functional.
14. Log out/in or use the client's native Reload UI action. Confirm all five positions, settings, normal/stealth slot contents and bindings persist. Repeat with a second character to confirm layout settings are independent. Disabling the addon should restore native binding routing; it must not rewrite saved keybindings.
15. Check the error/taint log and repeat steps 5–11 after a clean login. **Secure clicks, spell dragging, keybindings and combat behavior must all pass on the actual Forever client before calling the addon fully validated.**

Record each item as pass/fail/unavailable, with the exact build, error text and reproduction steps. Report unavailable combat-log data separately from addon defects. No one has executed these steps in the Cloud development environment.
